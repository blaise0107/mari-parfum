# MARI PARFUM — витрина

Статический сайт магазина парфюмерии: каталог, корзина, оформление заказа,
отправка заказа менеджеру в Telegram.

## Что где лежит

| Файл | Назначение |
|---|---|
| `index.html` | Главная: полка, фильтры, реестр цен, доставка и оплата |
| `product.html` | Страница аромата: флакон, пирамида нот, выбор объёма |
| `404.html` | Обрабатывает адреса вида `/product/<slug>` |
| `assets/catalog.js` | **Сгенерирован.** Не править руками |
| `assets/styles.css` | Тема «ателье»: тёплая база, шампанское золото, стекло |
| `assets/app.js` | Ядро: цены, корзина, диалоги, оформление, заказ |
| `assets/home.js` | Главная страница |
| `assets/product.js` | Страница товара |
| `assets/flacon.js` | Рисует флаконы (SVG) |
| `assets/flacons.css` | Оформление поверх `styles.css` |
| `assets/shelf.js` | Переключатель объёма на полке (идёт **до** `home.js`) |
| `tools/build-data.mjs` | Сборка данных, статики и версии ресурсов |
| `tools/serve.mjs` | Локальный просмотр |

Источники данных лежат на уровень выше, в корне проекта: `../catalog.json`
(товары) и `../settings.json` (цены, сегменты, объёмы, способы доставки и
оплаты, город, акция, контакты). Это те же файлы, что читает бот и которые
правит админка.

## Запуск локально

```sh
node tools/build-data.mjs     # после правки каталога или настроек
node tools/serve.mjs 4173     # http://localhost:4173
```

## Источник правды

Цены, промо, объёмы и сегменты берутся из `../catalog.json` и `../settings.json` —
тех же файлов, что читает Telegram-бот. Расхождение сайта с ботом недопустимо:
клиент увидит одну сумму, а менеджер выставит другую.

Арифметика повторяет `bot.py`:

- цена объёма = `price × ml ÷ base_ml` целочисленно;
- скидка — процент **только** от суммы товаров, доставка прибавляется после вычета;
- акция начисляется при сумме товаров от `promo.min_total`;
- «бесплатно от N ₽» тоже считается от суммы товаров — одна база для всех правил.

### Что менять и где

| Задача | Где |
|---|---|
| Добавить или изменить аромат | `../catalog.json`, затем пересборка |
| Цены, сегменты, объёмы | `../settings.json`, затем пересборка |
| Способы доставки и оплаты | `../settings.json → delivery_methods / payment_methods` |
| Внешние сервисы и их статус | `../settings.json → services` |
| Акция | `../settings.json → promo` |
| Город и регион | `../settings.json → city` |
| Менеджер и бот в Telegram | `../settings.json → manager_username / bot_username` |
| Телефон | `tools/build-data.mjs` (константа `PHONE`) — в `settings.json` его пока нет |
| Адрес витрины в соцсетях и поиске | `../settings.json → site_url` |

Черновики способов с пустым названием в `settings.json` (`new`) отбрасываются
при сборке — но лучше удалить их в самом боте.

## Что делает сборка

`tools/build-data.mjs` пишет `assets/catalog.js` и правит статические
HTML-страницы. Одно и то же значение нельзя держать в двух местах: город в
настройках и город в описании страницы разъезжаются, и поисковик получает
неверный `areaServed`. Поэтому сборка подставляет в разметку:

- `<meta name="description">` и `og:description` — цены, объёмы, город;
- JSON-LD (`areaServed`, `addressLocality`, `addressRegion`, `telephone`);
- подвал: базовый объём и условия акции;
- блок `<noscript>` с телефоном и ссылкой на Telegram — для тех, у кого
  JavaScript выключен;
- адрес бота в кнопках «Бот» (`data-bot-link`) — без JavaScript они тоже
  рабочие, а с работающим скриптом `app.js` перезаписывает его тем же;
- число товаров на странице 404.

Подстановка идемпотентна: каждый блок перезаписывается целиком, поэтому
повторная сборка ничего не наслаивает. Править эти места руками не нужно —
правьте `settings.json` и пересобирайте.

Отдельно про безопасность: данные в `catalog.js` — это JSON внутри
`<script>`, а HTML-парсер закрывает `<script>` на первой последовательности
`</script`, не глядя на кавычки в JS. Поэтому сборка экранирует `<`, `>` и
`&` (`\u003c` и т.д.) — иначе название товара из админки могло бы закрыть
тег и выполнить произвольный код у каждого покупателя.

## Доставка, оплата и подготовка к сервисам

Способы доставки и оплаты описаны в `settings.json` — в том же файле, что
читает бот. Отдельного файла для витрины больше нет: своя копия рано или
поздно разошлась бы с ботом, и админка при первом же сохранении её стёрла.
У каждого способа:

- `key` — тот же, что в боте, поэтому кнопки бота и витрины совпадают;
- `service` — какой внешний сервис за ним стоит (`cdek`, `boxberry`,
  `russianpost`, `sbp`, `sberbank`, `own`…);
- `status` — `live` работает сегодня, `planned` ждёт договора;
- `free_over` — сумма, от которой доставка бесплатна (только для витрины);
- `hint` — что менеджер скажет клиенту после заказа (пишется в подтверждение);
- `tags` — короткие метки для витрины («МО», «дёшево»).

Способы со `status: planned` **не показываются как варианты выбора** — вместо них
под списком появляется пометка «Скоро: …». Обещать оплату картой, которой ещё нет,
нельзя, но подготовка должна быть видна. Если способ недоступен, корзина считает
доставку по первому доступному, а не по недоступному.

`free_over` учитывают и витрина, и бот: доставка обнуляется, когда сумма
товаров до скидки достигла порога бесплатной доставки.

Чтобы включить реальные платежи: договор с ЮKassa или Тинькофф, ключи в
приёмнике заказов, `status` переключить на `live`.

## Стеклянные флаконы

Флаконы нарисованы авторским SVG (`assets/flacon.js`): прозрачный распылитель,
толстое стеклянное дно, трубка, глянцевая чёрная крышка и собственная этикетка
MARI PARFUM. Сторонние фотографии не загружаются и не копируются.

`MPFlacon.setFill(svg, ml, volumes)` обновляет жидкость и мениск одновременно.
Стекло, крышка и этикетка остаются неподвижными. Главная и страница товара
используют одну функцию. Переходы отключаются при `prefers-reduced-motion`.

Если появятся собственные фотографии, простая замена SVG на `<img>` не
сохранит эффект наполнения: для него понадобятся отдельные слои и маска.
Бэкап прежнего рисунка находится в корневом `data/backups/` проекта бота.

Шесть новинок импортированы 23.10.2026. Источники и временные цены за 10 мл
сохранены в `../README/CATALOG_SOURCES.md`. Если владелец меняет цену, отметка
«предварительная» больше не выводится; исторический источник остаётся в записи.

## Как уходит заказ

По умолчанию (без сервера) сайт **собирает** текст заказа и открывает чат
менеджера `@Mari13011` с уже подставленным текстом — клиенту остаётся нажать
«отправить». Рядом есть кнопка «Скопировать заказ». В тексте заказа видно,
какой сервис доставки выбран, — менеджеру не нужно переспрашивать.

Пока приёмник не подключён, заказ никуда не уходит, поэтому витрина так и
пишет: «Заказ собран, но ещё не отправлен». Обещать «заказ принят» при
пустом `ORDER_ENDPOINT` нельзя — клиент будет ждать звонка менеджера,
которого не будет.

Если нужен **автоматический** приём заказов без клика, поднимите приёмник на
serverless-хостинге (Cloudflare Workers / Pages Functions) и пропишите его
адрес в константу `ORDER_ENDPOINT` в начале `assets/app.js`:

```js
const ORDER_ENDPOINT = "https://<ваш-worker>.workers.dev/order";
```

Приёмник должен принять `POST` с JSON заказа и отправить его в Telegram через
Bot API. **Токен бота нельзя класть в клиентский JS** — он станет публичным, и
любой сможет читать переписку с покупателями и слать боту команды.
